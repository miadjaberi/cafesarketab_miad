## یافته‌ها و اصلاحات
1. **ترتیب patchها — `ui-layer-fix.js`:** اسکریپت‌های پویا با `async=true` تزریق می‌شدند و ترتیب اجرای boot، ناوبری خرید و ناوبری نهایی تضمین نبود. تزریق اکنون با `async=false` و به ترتیب فهرست انجام می‌شود.
2. **دوگانگی کنترل‌گر شرایط — `fix-four-bugs.js` و `boot-flow-fix.js`:** دو فایل جداگانه در نمایش/مخفی‌کردن شرایط و اسپلش دخالت داشتند. مالک نمایش اکنون فقط `boot-flow-fix.js` است؛ فایل چهار باگ فقط ظاهر و بستن مودال را مدیریت می‌کند.
3. **ورود با پروفایل تأییدنشده — `boot-flow-fix.js`:** مسیر قبلی بعد از وجود session اما شکست خواندن پروفایل، با `profile || getLocalCafeUser()` رابط اصلی را باز می‌کرد؛ تایمر ایمنی نیز بدون تشخیص آفلاین می‌توانست کاربر محلی را وارد کند. اکنون ورود آنلاین فقط با پروفایل سرور مجاز است و کاربر محلی فقط در مسیر آفلاینِ انتخاب‌شده قابل استفاده است.
4. **ناوبری چهارصفحه‌ای — `main.js`:** شنونده قدیمی اسکرول تابع داخلی `updateBottomNav` را صدا می‌زد و با مالک نهایی ناوبری هماهنگ نبود. اکنون نوار پایین از `window.updateBottomNav()` مالک نهایی همگام می‌شود.
5. **کش پوسته — `sw.js`:** شکست یک فایل در `cache.addAll` کل precache را متوقف می‌کرد. فایل‌ها اکنون مستقل cache می‌شوند؛ URLهای نسخه‌دار patchها و آیکون‌های محلی افزوده و نسخه کش عوض شده است.
6. **ابزار QA — `ui-layer-fix.js` و `sw.js`:** تزریق QA از boot عادی غیرفعال و فایل‌های QA از precache خارج شدند؛ فایل‌ها حذف نشده‌اند.

## تکمیل ضروری پس از بازبینی دوم — تشخیص اینترنت و آیکون نصب آفلاین

### ۷. تشخیص اشتباه آنلاین‌بودن — `boot-flow-fix.js`
در مسیر قبلی، هر پاسخ HTTP از چند نشانی (حتی پاسخ fallback کش‌شدهٔ صفحه اصلی) به معنی آنلاین‌بودن تلقی می‌شد. Service Worker در قطع اینترنت می‌تواند برای بعضی درخواست‌های عادی صفحهٔ index را به‌عنوان fallback برگرداند؛ در نتیجه برنامه ممکن بود تصور کند اینترنت آماده است، درحالی‌که Supabase قابل دسترس نبود.
اصلاح تکمیلی: سنجش اتصال فقط با درخواست GET مستقیم به `/auth/v1/health` سوپابیس، بدون کش و با بررسی `response.ok` انجام می‌شود. این معیار با نیاز واقعی ورود آنلاین هم‌راستاست.

### ۸. وابستگی آیکون نصب PWA به Storage آنلاین — `manifest.webmanifest`
آیکون‌های manifest قبلاً از Supabase Storage خوانده می‌شدند، در حالی که نسخه‌های محلی `icon192.png` و `icon512.png` در مخزن موجود و در Service Worker نیز precache شده‌اند.
اصلاح تکمیلی: manifest اکنون از دو آیکون محلی استفاده می‌کند تا نمایش آیکون نصب به دسترسی لحظه‌ای Storage وابسته نباشد.


### ۹. جلوگیری از پایان زودهنگام تایمر راه‌اندازی — `boot-flow-fix.js`
بازبینی مرحله‌ای نشان داد تایمر ایمنی ۴ثانیه‌ای از ابتدای مسیر شروع می‌شد، در حالی که بررسی شبکه تا ۳ ثانیه، انتظار نشست تا ۳٫۵ ثانیه و خواندن پروفایل تا ۴ ثانیه مهلت مستقل داشتند. در شبکه کند، تایمر کلی می‌توانست قبل از تمام‌شدن مسیر معتبر، صفحه ورود را باز کند.
اصلاح تکمیلی: مهلت ایمنی کلی اکنون مجموع مهلت شبکه، نشست و پروفایل به‌اضافه ۵۰۰ میلی‌ثانیه است؛ هر مسیر موفق همچنان تایمر را زودتر پاک می‌کند.


### ۱۰. جلوگیری از پاسخ HTML برای فایل‌های آفلاینِ گم‌شده — `sw.js`
در مسیر fallback عمومی، هر درخواست غیر API که در شبکه شکست می‌خورد و در کش هم نبود، پاسخ `index.html` دریافت می‌کرد. برای درخواست تصویر، CSS، فونت یا منبع دیگر، این پاسخ از نوع HTML است و می‌تواند به‌صورت تصویر شکسته یا منبع نامعتبر دیده شود.
اصلاح تکمیلی: fallback به `index.html` فقط برای درخواست‌های navigation مجاز است. برای منابع غیر navigation، ابتدا فقط همان URL از کش خوانده می‌شود و در صورت نبودن، `Response.error()` برمی‌گردد؛ بنابراین خطای واقعی پنهان نمی‌شود و HTML به‌جای فایل تحویل داده نمی‌شود.


### ۱۱. اصلاح جریان ورود و بازیابی ثبت‌نام نیمه‌تمام — 2026-11-08

- `main.js`: موفقیت ورود اکنون وابسته به نشست Supabase و تطبیق شناسه کاربر با پروفایل سرور است؛ اطلاعات محلی هر دو فیلد `id` و `user_id` را نگه می‌دارد و پس از تأیید راه‌انداز، پیام موفقیت می‌دهد.
- `boot-flow-fix.js`: تشخیص موفقیت بر اساس `display` صفحه‌ها حذف شد. راه‌انداز دیگر از روی ظاهرشدن صفحه اصلی موفقیت ورود را حدس نمی‌زند و وجود شناسه واقعی پروفایل سرور را الزام می‌کند.
- `supabase/functions/phone-pin-auth/index.ts`: برای حساب Auth ساخته‌شده اما پروفایل جاافتاده، بازیابی محدود اضافه شد. بازیابی فقط پس از ورود موفق با همان شماره و PIN و تأیید metadata مخصوص phone-login انجام می‌شود؛ رمز بازنشانی نمی‌شود، حسابی حذف نمی‌شود و نقش غیر user یا شماره ناسازگار خودکار تغییر نمی‌کند.
- `main.js`: پاسخ بازیابی‌شده با پرچم `recovered` به‌عنوان نتیجه معتبر ثبت‌نام نیمه‌تمام پذیرفته می‌شود.
- تغییرات فقط در شاخه آزمایشی ثبت شده‌اند؛ دیتابیس، داده کاربران، OTP مدیر و `main` دست‌نخورده‌اند.
